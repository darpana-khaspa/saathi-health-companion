PRODUCT
Name: Saathi Health Companion
Purpose: An offline-first, low-connectivity assistant for trained ASHA/ANM frontline health workers. It answers questions only from supplied official public-health protocol documents, cites the exact protocol section for every answer, detects danger signs using a hard-coded rules layer before any model response, and helps prioritise household follow-up visits.

NON-NEGOTIABLE SAFETY RULES
1. This is a decision-support demo, not a doctor and not a replacement for official clinical guidance.
2. Never invent clinical thresholds, diagnoses, treatment, or medication dosages. Never answer antibiotic-dose requests; clearly redirect to a qualified clinician / approved pathway.
3. Build deterministic, hard-coded danger-sign rules that run BEFORE retrieval or model generation. Include a configurable rule list and tests. At minimum, match clear terms/phrases for bleeding during pregnancy and serious newborn danger signs, and provide a visible urgent-referral message. Do not rely on an LLM to detect these.
4. Add an evaluation script/test suite that verifies 100% detection of the supplied must-escalate test set. If any required case fails, tests must fail.
5. If a question is outside the supplied protocol corpus, say so, do not guess, and redirect to the official protocol or a clinician.
6. Every normal answer must cite source document name and section/page/chunk. If no reliable source is retrieved, refuse to answer substantively.
7. Display a clear disclaimer and an obvious escalation state. Do not claim the prototype is clinically validated.
8. Use synthetic data only. Do not collect real patient-identifiable information in the demo.

DELIVERABLES
- A clean, responsive frontend and a working backend, not a static landing page.
- Offline-capable protocol search and Q&A using local documents/index; core flow must still work with no internet after setup.
- A deterministic escalation layer, citation-grounded retrieval, household visit list, sample data, automated tests, README, and deployment instructions.
- Actually run the app and tests. Never fabricate test results, metrics, URLs, or a successful deployment.

TECH STACK (choose a practical stack and keep it simple)
Use Python + FastAPI backend. Use a lightweight React + Vite + TypeScript frontend if the workspace supports it; otherwise use the simplest robust frontend compatible with the existing project. Use SQLite for the synthetic household register and local persistence. Use a lightweight local retrieval approach (TF-IDF/BM25 or small local embeddings) that does not require a cloud API. Keep the architecture modular so a small local language model can be added, but do not make the MVP depend on a huge model or GPU. If a local model is available, make it optional and configurable; never silently fall back to an external API. Provide an extractive/template answer fallback that quotes only retrieved approved protocol text.

- Provide a “Why this answer?” expandable area showing retrieved protocol excerpts and match details.
- Include a few example question chips sourced from the synthetic evaluation set.

- Sidebar/navigation should be minimal; use at most two main tabs: “Ask Protocols” and “Visit List”. Put a compact status strip for Offline/Online and local protocol readiness.
